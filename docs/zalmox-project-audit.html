Project Audit: Zalmox (CasaEmil)

Overall rating: 7.8 / 10 (B+) — A mature, security-conscious multi-tenant hospitality PMS with strong engineering discipline, held back by documentation drift, styling debt, and an in-flight rebrand.

Generated: Tuesday, 7 July 2026 · Repository: CasaEmil / Zalmox v0.2.0

Executive summary

This is not a starter template dressed up as a product. It is a full-featured property management system (Gantt calendar, check-in with MRZ/passport scanning, fiscal invoicing, guest app, public booking site, platform admin, multi-tenant routing) built on a modern stack with unusually good architectural guardrails for a project at v0.2.0.

The codebase is production-capable with conditions — matching your own docs/PRODUCTION-READINESS.md verdict — but it is mid-migration (hospira → platform-admin / Zalmox rebrand) and carries measurable technical debt.

Dimension ratings

1. Architecture

8.5 / 10

Strengths

  • Clear layer model documented in ARCHITECTURE.md: domain/ → services/ → features/ → components/ → app/
  • Import boundaries enforced in CI tests — strict rules for domain/features/services with zero tolerance
  • Domain logic is genuinely pure (booking conflicts, gantt math, check-in validation, fiscal VAT, guest dedup)
  • Multi-tenant kernel in core/ with plan gates and module registry
  • proxy.ts is a serious edge middleware: tenant resolution, MFA, alpha gate, team permissions, i18n

Debt

  • 58 components → app imports tracked as a baseline cap (not shrinking yet)
  • services/availability-month.ts imports a component helper (inverted dependency)
  • Many routes still call services/ directly instead of thin loaders
  • features/ is underused relative to components/ (~1,165 TS files total)

2. Security & multi-tenancy

8.5 / 10

Strengths

  • Documented tenant isolation rules in docs/tenant-security.md
  • Static tenant query audit (audit-tenant-queries.ts) catches IDOR footguns in services
  • 92 Supabase migrations including RLS hardening (045_tenant_rls_bulletproof.sql, 076_settings_rls_bulletproof.sql)
  • MFA policy, alpha gate, rate limiting, team permission paths enforced at edge
  • Host-based tenant resolution — no "first tenant in DB" fallback in production

Gaps

  • Static audit is pragmatic, not exhaustive
  • Rebrand leaves legacy HOSPIRA_* env vars and docs references
  • Sensitive guest data (CNP, MRZ, national IDs) — security is thoughtful but the blast radius is high if anything slips

3. Testing

8.5 / 10

Strengths

  • 1,296 unit/integration tests across domain, lib, services, layout, hooks
  • Dedicated security test suite
  • Import boundary + tenant query audits as tests
  • 8 Playwright e2e specs (auth, booking, admin nav, mobile compat, public calendar)

Gaps

  • No visible GitHub Actions / CI pipeline (.github/ absent)
  • E2E coverage is thin relative to surface area (154 routes)
  • Component-level tests are sparse (mostly domain/lib)

4. Code quality

7.5 / 10

Strengths

  • strict: true TypeScript
  • Zod schemas for settings/forms
  • Consistent patterns: server actions, requireTenantIdForData(), error formatting
  • Build and typecheck both pass on Next.js 16 + React 19

Weaknesses

  • ESLint: 97 warnings (mostly unused vars), 3 errors (prefer-const, @ts-ignore)
  • Large files: proxy.ts (~650 lines), heavy admin components
  • Active rename leaves mixed naming (hospira, platform-admin, Zalmox in ARCHITECTURE.md)
